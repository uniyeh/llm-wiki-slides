# DSOD（2026）

## 一句話摘要
借用大型視覺基礎模型 DINOv2 的「不偏心」特徵，幫 SFOD 模型擺脫只懂來源領域的[[source-bias]]，再用蒸餾做出不需 DINOv2 的輕量版。（DSOD, p.1）

## 要解決的問題
- [[source-free-adaptation|SFOD]] 只有「來源預訓練模型 + 沒標註的目標資料」，比 UDAOD 更容易出現 **Source Bias**：調整後的模型仍偏向來源領域，泛化差，且在自我訓練中誤差越滾越大。（DSOD, p.1）
- 原因：UDAOD 可同時看兩個領域資料學「跨領域共通特徵」，SFOD 只能看目標資料。（DSOD, p.1–2）

## 方法（白話＋技術）
**白話**：原本的偵測模型是「只在晴天城市練過的老司機」，DSOD 找來一位「看過全世界照片的通才顧問」（DINOv2）坐副駕，一邊補充看法、一邊提醒老司機別只用舊習慣判斷。

**技術**（建立在 [[detr|Deformable-DETR]] + [[mean-teacher]] 上，p.3）：
1. **UFI（Unbiased Feature Injection）**：DINOv2 特徵經 SSE（Simple Scale Extension，線性投影＋雙線性插值）對齊成 CNN 的多尺度特徵，再以「加法」融合：F_fuse = F_CNN + w·F_DINO。作者主張兩模型特徵近似正交，相加不會互相覆蓋。（p.4–5）
2. **SAFR（Semantic-Aware Feature Regularization）**：把 [[pseudo-label|偽標籤]]框轉成高斯熱圖，只在「前景（物體）區域」要求 CNN 特徵貼近 DINOv2 特徵（加權 MSE）。（p.5）
3. **DAAW（Domain-Aware Adaptive Weighting）**：融合權重 w 太大會讓預測不穩。先用少量目標圖做敏感度測試，計算分類／定位／聯合穩定度，取曲線「手肘點」當 w，再用平方根 warm-up 慢慢加上去。（p.5–6）
4. **DSOD-Distill**：用「EMA 老師 + 已調好的 DSOD 靜態老師」雙老師、在 loss 層級融合監督訊號，把知識[[knowledge-distillation|蒸餾]]到不含 DINOv2 的一般模型，方便部署在邊緣裝置。（p.6）

## 實驗設定（資料集、指標）
- 偵測器：Deformable-DETR + ResNet-50；VFM：DINOv2 ViT-B/Reg。沿用 DRU 的設定與來源預訓練權重。（p.7）
- 三種 [[benchmarks|領域落差任務]]：Cityscapes→Foggy Cityscapes（天氣）、Cityscapes→BDD100k（場景）、Sim10k→Cityscapes（合成→真實）。指標 mAP@IoU0.5。（p.7）

## 主要結果
| 任務 | Source only | DSOD | DSOD-Distill | Oracle（目標有標註） | 來源 |
|---|---|---|---|---|---|
| 晴→霧 | 29.5 | **48.1** | 46.9 | 48.7 | Table 1, p.8 |
| 城市→BDD | 29.1 | 39.2 | 36.7 | 66.2 | Table 2, p.9 |
| 合成→真實（car AP） | 48.9 | **61.4** | 60.6 | 75.9 | Table 3, p.9 |

- 晴→霧任務中 DSOD 從 Source only 的 29.5 提升到 48.1。（Table 1, p.8）⚠️ 該列各類別平均只有 46.4，見「矛盾」。
- 消融（晴→霧）：MT 基線 39.6 → +UFI 43.0 → +SAFR 45.5 → +DAAW 45.8 → +DRU 48.1。（Table 4, p.9）
- 融合權重超過約 0.4 後 AP 急降，驗證「加太多外部特徵會擾亂模型」。（Fig. 6, p.10）

## 限制
- 城市→BDD 任務沒有贏過 DDT（39.6 vs 39.2）；作者自承未達整體 SOTA。（p.7, Table 2）
- 雙塔架構訓練與推論都更耗算力，需靠 Distill 版補救。（p.6）

## 矛盾
已用「把表格各類別分數自己平均一次」的方式驗算（2026-11-21）：

| 數字 | 摘要（p.1） | 表格的 mAP 欄 | 表格各類別的平均（自算） | 內文推算 |
|---|---|---|---|---|
| 跨場景 城市→BDD | 39.3 | 39.2（Table 2, p.9） | 38.5 | 38.6（「贏 MRT 4.9、贏 DRU 2」, p.7） |
| 晴→霧 | 48.1 | 48.1（Table 1, p.8） | 46.4 | 48.1（「贏 DRU 4.5、贏 DDT 2.6」, p.7） |
| 晴→霧 DSOD-Distill | — | 46.9（Table 1, p.8） | 46.5 | 47.0（「只掉 1.1」, p.7） |

- 同一張表的其他方法（Source only、DRU、DDT、Oracle）自算平均都和 mAP 欄一致，只有 DSOD 這兩列對不上 → 無法判斷哪個才是正確值。
- **決策（使用者，2026-11-21）**：無法確認時以表格 mAP 欄為準 → 跨場景用 **39.2**、晴→霧用 **48.1**、Distill 用 **46.9**。
- 因為晴→霧的 48.1 有疑慮，簡報**不說**「幾乎追上 Oracle」，只說「從 29.5 提升到 48.1」。
